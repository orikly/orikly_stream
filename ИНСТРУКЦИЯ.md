# Orikly Quest Stream — что делать по шагам

В пакете:
- `orikly-quest-stream/` — весь проект, его загружаете в GitHub;
- `build.yml` — файл сборки. Он отдельно, потому что Mac прячет папки с точкой (`.github`), и через сайт такую папку проще создать вручную;
- эта инструкция.

---

## Шаг 1. Ключ подписи (Терминал на Mac)

Ключ подписи (keystore) — файл, которым подписывается приложение. HMS обновляет приложение только при той же подписи. **Не теряйте его и пароль.**

1. Откройте Терминал и проверьте, есть ли Java:
   ```
   java -version
   ```
   Если пишет, что Java нет: скачайте с https://adoptium.net установщик **Temurin 17 (.pkg для macOS)**, установите и перезапустите Терминал.

2. Создайте ключ на рабочем столе:
   ```
   cd ~/Desktop
   keytool -genkeypair -v -keystore orikly-release.jks -alias orikly -keyalg RSA -keysize 2048 -validity 10000
   ```
   - Придумайте пароль и запишите его. Это пароль и для файла, и для ключа.
   - На вопросы про имя и организацию можно ответить что угодно или просто нажимать Enter.
   - В конце на вопрос «правильно?» ответьте `yes` (или `да`).

3. Сохраните копию `orikly-release.jks` в надёжное место. **В GitHub этот файл не загружайте.**

## Шаг 2. Репозиторий на GitHub

1. Репозиторий должен быть **публичным**, иначе HMS не скачает APK по ссылке.
   Проверить: Settings → внизу Danger Zone → Change visibility.
   В публичном коде нет ни паролей, ни ключа доступа: они хранятся в секретах (шаг 3).

2. Загрузите проект: на странице репозитория **Add file → Upload files**.
   В Finder откройте папку `orikly-quest-stream`, выделите всё (Cmd+A) и перетащите в окно браузера.
   Внизу нажмите **Commit changes**.

3. Создайте файл сборки: **Add file → Create new file**.
   - В поле имени наберите `.github/workflows/build.yml`. После каждого `/` GitHub сам создаёт папку.
   - Откройте `build.yml` из пакета (двойной клик или в TextEdit), скопируйте весь текст и вставьте в большое поле.
   - Нажмите **Commit changes**.

4. Проверьте, что в корне репозитория есть: `app`, `gradle`, `viewer`, `.github`, `gradlew`, `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`.

---

## Шаг 3. Пять секретов

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**. Создайте пять штук; Name вписывайте ровно так, как здесь:

| Name | Secret (значение) |
|---|---|
| `KEYSTORE_PASSWORD` | пароль из шага 1 |
| `KEY_ALIAS` | `orikly` |
| `KEY_PASSWORD` | тот же пароль из шага 1 |
| `STREAM_KEY` | придумайте ключ доступа к трансляции без пробелов, например `aula-7Kq2xP` (запишите, нужен на ноутбуке) |
| `KEYSTORE_BASE64` | см. ниже |

Для `KEYSTORE_BASE64` выполните в Терминале:
```
cd ~/Desktop
base64 -i orikly-release.jks | pbcopy
```
Команда ничего не выведет, просто скопирует текст. Сразу вставьте его (Cmd+V) в поле Secret.

## Шаг 4. Сборка APK

1. В репозитории откройте вкладку **Actions**. Если GitHub попросит, включите workflows (зелёная кнопка).
2. Слева **Build APK** → справа **Run workflow** → в поле версии `0.1.0` → **Run workflow**.
3. Через 5–10 минут появится зелёная галочка.
   Красный крестик: откройте запуск, скопируйте текст ошибки и пришлите мне.
4. Справа на главной странице репозитория, в **Releases**, появится `v0.1.0` с файлом `orikly-quest-stream.apk`.

**Ссылка для HMS** (вставьте свой логин и имя репозитория):
```
https://github.com/ЛОГИН/РЕПОЗИТОРИЙ/releases/latest/download/orikly-quest-stream.apk
```
Ссылка не меняется. Для следующей версии снова Run workflow с номером побольше (`0.1.1`, `0.2.0`), и HMS обновит очки по той же ссылке.

## Шаг 5. Очки (один раз)

1. Через HMS поставьте приложение на **одни** очки (сначала пробуем на одних).
2. Откройте **Orikly Stream** → **Iniciar transmisión** → в системном окне выберите **Pantalla completa** → **Empezar**.
3. На экране будут IP и статус «transmitiendo». Запишите IP.
4. Можно выйти из приложения и запускать любые другие: трансляция работает в фоне.

---

## Шаг 6. Ноутбук

1. Перетащите файл `viewer/index.html` из пакета в окно **Chrome**. Удобно сохранить его в закладки.
2. **Settings** → впишите `STREAM_KEY`, имена и IP очков → **Save**. Chrome запомнит.
3. **Choose folder…** → выберите папку для записей. Chrome запомнит и при первом старте спросит разрешение — разрешите.
4. **Start all** (или **Start** на одной плитке): пойдёт картинка и запись. **Stop**: файл `Q3-01_дата_время.mp4` сохранится в папку.
   - Если снять галочку **Record**, будет только просмотр без записи.
   - Клик по картинке разворачивает на весь экран, Esc возвращает.
5. Если Chrome спросит про доступ к устройствам в локальной сети, разрешите.
6. Не закрывайте вкладку во время записи: файл дописывается в момент Stop.

## Шаг 7. Что проверить и прислать мне

1. Есть ли картинка: в меню Quest и внутри приложений урока (Open Brush, Mission: ISS и т.д.). Чёрный экран — тоже результат, напишите, в каких приложениях.
2. Имя на плитке и в приложении совпадает с именем из HMS?
3. Задержка: на очках часы с секундами, сравнить с ноутбуком.
4. **Главное:** Stop и Start с ноутбука несколько раз подряд. На очках ничего подтверждать не надо?
5. Снять очки, подождать, пока уснут, надеть, нажать Start на ноутбуке. Картинка вернулась без подтверждения?
6. Оставить на ночь на зарядке, утром Start. Работает?
7. Записанный файл открывается и нормально проигрывается?
