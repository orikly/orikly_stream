# Orikly Quest Stream — CLAUDE.md

Инструкции для Claude Code. Владелец проекта — Paul (Orikly, НКО, VR-уроки в публичных школах Испании). Код Paul не пишет: его пишешь ты, Paul собирает через GitHub Actions и ставит APK на очки через HMS. Общайся с ним по-русски, коротко, без воды.

## Цель

Учитель (или наблюдатель от школы) на ноутбуке в браузере видит живую картинку со всех очков класса одновременно — сеткой, с разворотом одного окна по клику.

- Парк: 10 очков, все — Meta Quest 3. Других моделей нет.
- Режим очков: на ВСЕХ очках Individual Mode (не Shared Mode), у каждого ученика свой аккаунт организации. Управление — Meta Horizon Managed Solutions (HMS).
- Режим разработчика на очках НЕ включён, ADB недоступен. Установка только через HMS по прямой ссылке на APK.
- Сеть: свой роутер в классе, возможно без выхода в интернет. Всё должно работать только в локальной сети.
- Ноутбук наблюдателя подключён к той же сети по Wi-Fi.

## Требования к стриму

- Разрешение: 480p по высоте (кадр с Quest квадратный ~1024×1024 → по умолчанию 480×480). Настраиваемо.
- Частота: 10 кадров/с по умолчанию. Настраиваемо (5–24).
- Задержка: не более 1 секунды.
- Нагрузка: минимальная, суммарно на 10 очков — десятки Мбит/с максимум.
- Звук не нужен.
- На очках ничего не записывать. Запись видео — только на ноутбуке, в браузере (страница наблюдателя).

## Главное требование: одно подтверждение

На очках захват подтверждается ОДИН раз (системное окно MediaProjection) и дальше держится постоянно, пока очки не перезагрузятся. Перед каждым уроком на очках ничего не нажимаем: трансляцию и запись запускают и останавливают с ноутбука.

- «Стоп» с ноутбука = закрыть поток; захват на очках НЕ останавливается (иначе нужно новое подтверждение).
- Пока никто не смотрит, очки не сжимают JPEG (только держат последний кадр в памяти раз в секунду).
- Новое подтверждение неизбежно после: перезагрузки, штатного каста Meta, закрытия приложения из списка запущенных; возможно — после сна (проверить).
- Запасной путь, если сон/перезагрузки убивают захват: AccessibilityService.takeScreenshot (включается один раз в настройках, ~3 кадра/с; на Quest под HMS может быть недоступен).

## Архитектура

### 1. Android-приложение на очках (`app/`)

Kotlin, 2D-приложение (панель), без VR-интентов.

- `minSdk 29`, `targetSdk 34`, `compileSdk 35`.
- Захват: `MediaProjection` → `VirtualDisplay` → `ImageReader` (RGBA_8888).
- Обработка: ограничение частоты кадров, масштабирование до целевого размера, сжатие в JPEG (качество ~60, настраиваемо).
- Отдача: встроенный HTTP-сервер на порту `8080`. Лёгкая зависимость (Ktor server CIO или аналог), без тяжёлых фреймворков.
- Работа в фоне: foreground service с типом `mediaProjection`, `PARTIAL_WAKE_LOCK`, `WifiLock` (режим высокой производительности, чтобы энергосбережение Wi-Fi не давало лагов).

Эндпоинты:
- `GET /stream` — MJPEG (`multipart/x-mixed-replace`), несколько клиентов одновременно.
- `GET /snapshot.jpg` — один последний кадр.
- `GET /status` — JSON: имя устройства, модель, IP, идёт ли захват, fps, заряд батареи, RSSI Wi-Fi.
- Все эндпоинты требуют параметр `?key=<ключ>`. Ключ задаётся в настройках приложения (один на весь класс). Без ключа — 403.

Сценарий запуска:
1. Paul перед уроком открывает приложение на очках.
2. На экране: имя устройства, IP, порт, статус, поле ключа, кнопка «Начать трансляцию».
3. Кнопка → `MediaProjectionManager.createScreenCaptureIntent()` → системное окно согласия. Пользователь выбирает «Весь экран» (на Android 14 есть вариант «одно приложение» — он не подходит; подсказать это текстом на экране).
4. Сначала стартует foreground service, потом вызывается `getMediaProjection()` (требование Android 14). Токен одноразовый — не переиспользовать.
5. Дальше приложение работает в фоне, пока ученик в других приложениях.

Обработка ошибок:
- Обрабатывать `MediaProjection.Callback.onStop()` (например, если кто-то запустил штатный каст Meta — система забирает захват). Показать статус «Остановлено» и уведомление; перезапуск — только через новое согласие.
- Если HTTP-клиент отвалился — не ронять сервис.

Окно согласия обойти нельзя (нет системной подписи и нет ADB). Не пытайся его обходить. Цель — одно нажатие на очки за урок.

Имя устройства: настраиваемое в приложении (например, `Q3-01`), по умолчанию `Build.MODEL` + последние символы `ANDROID_ID`.

### 2. Страница наблюдателя (`viewer/index.html`)

Один статический HTML-файл, открывается на ноутбуке локально (`file://`). Без сборки, без внешних зависимостей, без интернета.

- Конфиг вверху файла: массив `{ name, ip }` на 10 очков, порт, ключ. Ключ и список очков можно поменять кнопкой Settings (хранится в localStorage браузера).
- Сетка 5×2 (адаптивно), в каждой плитке `<img src="http://IP:8080/stream?key=...">` и подпись с именем.
- Статус плитки: «в сети» / «нет связи»; при обрыве — автоматическое переподключение каждые 3 с.
- Клик по плитке — разворот на весь экран; Esc или повторный клик — назад к сетке. Развёрнутая плитка переподключается с `?hq=1`: очки отдают 960p, JPEG 80 (захват идёт в 960p, обычный поток уменьшается до 480p). Запись всегда 480p с отдельного canvas фиксированного размера.
- Небольшая строка состояния из `/status` (батарея, сигнал Wi-Fi) — опрос раз в 10 с.
- Кнопки Start/Stop на каждой плитке и «Start all / Stop all». Start = поток + запись (галочка Record).
- Поток читается через `fetch` (сами режем multipart), рисуется в `<canvas>`, запись — `canvas.captureStream()` + `MediaRecorder` (MP4/H.264 в Chrome, иначе WebM), файлы пишутся в выбранную папку (File System Access API) кусками раз в 2 с; без папки — скачивание при остановке.
- Сервер отвечает на `OPTIONS` с `Access-Control-Allow-Private-Network: true` (ограничения Chrome на доступ к локальной сети со страницы `file://`).

IP очков фиксируются через резервирование DHCP на роутере — это делает Paul, приложение только показывает свой IP.

### 3. Сборка и выдача APK (`.github/workflows/build.yml`)

- GitHub Actions собирает release APK: вручную через сайт (Run workflow с версией) или при пуше тега `v*`.
- Подпись: keystore хранится в GitHub Secrets (base64), ключ постоянный — иначе HMS не сможет обновлять приложение поверх старого.
- `versionCode` растёт с каждым релизом (из номера тега или номера запуска).
- APK публикуется как asset GitHub Release с постоянным именем, чтобы работала ссылка вида `https://github.com/<owner>/<repo>/releases/latest/download/orikly-quest-stream.apk` — её Paul вставляет в HMS.
- В README коротко: как создать keystore, какие секреты добавить, как выпустить релиз.

### 4. Режим через интернет (`server/`, `RelayClient.kt`)

Причина: в школе ноутбук не пускают в школьный Wi-Fi (MAC не прописан), очки могут быть только в школьном Wi-Fi. Ноутбук в том же классе, интернет — с iPhone (безлимит). Смотрит только этот ноутбук.

- Очки сами держат WebSocket к `RELAY_URL` (секрет GitHub, зашивается в APK; пусто — режим выключен): `wss://stream.<домен ассоциации>/push?key=STREAM_KEY`.
- Протокол: очки → сервер text `{"type":"hello",name,model,version}`, `{"type":"status",...}` раз в 10 с, binary = JPEG; сервер → очки `{"type":"want","on":bool,"hq":bool}`. Кадры шлются только при `on`. Если очередь отправки > 512 КБ — кадр выбрасывается (задержка не копится). Переподключение 2→30 с, ping 20 с.
- Ноутбук (Windows): `orikly-server.exe` (Go, gorilla/websocket), слушает только `127.0.0.1:8090`. Страница `viewer/index.html` встроена в exe; на `http://` она работает в режиме сервера: очки находятся сами по именам (`/api/devices`), поток `/stream/<имя>[?hq=1]` в том же MJPEG-формате. Всё, кроме `/push`, отвечает только локально (запросы через Cloudflare несут `Cf-Connecting-Ip` → 404).
- Постоянный адрес — Cloudflare Tunnel (cloudflared как служба Windows), домен ассоциации перенесён в Cloudflare DNS, public hostname `stream.<домен>` → `http://localhost:8090`.
- Ключ сервера хранится в `orikly-server.json` рядом с exe (спрашивается при первом запуске).
- Записи — в папку Google Диска для компьютера (Workspace ассоциации), выбирается кнопкой «Choose folder…».
- Локальный режим (страница как файл, очки по IP) остаётся рабочим.

## Объём трафика (для проверки)

MJPEG 480×480, 10 fps, качество 60 ≈ 20–35 КБ на кадр → ~2–3 Мбит/с на очки, ~20–30 Мбит/с на 10 очков. Для Wi-Fi 6 роутера это нормально. Если выйдет больше — снижать качество JPEG и fps, а не разрешение.

## План проверки (на одних очках, до массового развёртывания)

1. Установка через HMS по ссылке, запуск, согласие, картинка в браузере.
2. Захват в каждом приложении урока (иммерсивные приложения могут блокировать захват — тогда будет чёрный экран):
   Enhance VR, Open Brush, Open Blocks, Mission: ISS, Trace Artist, Tablecraft, Hand Puzzles, Beat the Beats, Archery Pro.
3. Не убивает ли Horizon OS фоновый сервис при запуске иммерсивного приложения и за 45 минут урока.
4. Задержка: на очках открыть часы с секундами, сравнить с ноутбуком. Цель — ≤1 с.
5. Трафик и нагрев/батарея за 45 минут.
6. Поведение после сна очков и после перезагрузки: жив ли захват без нового подтверждения (снять очки до засыпания, надеть; оставить на ночь на зарядке).
