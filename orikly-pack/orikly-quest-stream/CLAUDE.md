## Цель

Учитель (наблюдатель) на ноутбуке в Chrome видит живую картинку со всех очков класса — сеткой; клик — разворот одних очков на весь экран в лучшем качестве. Запись каждого потока в MP4 на ноутбук (в папку Google Диска ассоциации).

## Железо и сеть (как есть сейчас)

- **10 очков, две модели: Meta Quest 3 и Quest 3S.** Management — Meta Horizon Managed Solutions (HMS), Individual Mode, у каждого ученика свой аккаунт. Режима разработчика и ADB нет. Установка только через HMS по прямой ссылке на APK.
- **Очки — только в школьном Wi-Fi** (другую сеть на них поставить нельзя). Интернет у школьного Wi-Fi есть. Скорость отдачи школьного Wi-Fi не измерена.
- **Ноутбук в школьный Wi-Fi не пускают** (MAC не прописан). Ноутбук в том же классе, интернет — **с iPhone** (iOS 15, безлимит). Paul видел на ноутбуке upload ~1–2 Мбит/с; download не измерен.
- Поэтому основной режим — **через интернет**: очки → интернет → Cloudflare → туннель → ноутбук.
- Ноутбуки: **Windows** (`DESKTOP-IAG08AS`) — основной; **MacBook Air M1** (`kiros-MacBook-Air.local`) — разработка и проверки.
- Смотрит только один ноутбук, один человек.

## Требования к трансляции

- **10 кадров/с на каждых очках** — жёстко (Paul). Задержка — минимальная, без накопления. Всегда отправлять самый свежий кадр.
- Обычный кадр 480p (кадр Quest квадратный), JPEG 60. Развёрнутые очки — 960p, JPEG 80.
- Если канала не хватает — снижать качество (сначала JPEG, потом разрешение), а не частоту.
- **Eco (1 кадр/с остальным при развороте) — Paul отказался:** везде обычный поток. Не предлагать снова.
- Звук не нужен. На очках ничего не записывать; запись только на ноутбуке.

## Главное требование: одно подтверждение на очках

Захват экрана подтверждается на очках **один раз** (системное окно MediaProjection → «Pantalla completa» → «Empezar»), дальше держится постоянно. Трансляцию и запись запускают и останавливают с ноутбука («Стоп» = закрыть поток, захват на очках не останавливается).
Новое подтверждение неизбежно после: перезагрузки очков, обновления APK, штатного каста Meta, закрытия приложения из списка запущенных; возможно — после сна (не проверено).
Окно согласия обойти нельзя (нет системной подписи и ADB) — не пытаться. Запасной путь, если понадобится: `AccessibilityService.takeScreenshot` (~3 кадра/с, на Quest под HMS может быть недоступен).

## Архитектура

Номер версии в коде не хранится: это то, что Paul вписывает при запуске сборки (на очках сейчас `0.4.4`). Код 0.4.4 = 0.3.4 (0.3.5/0.3.6 в GitHub так и не попали). Следующая сборка добавляет: диагностику кадров, исправление обрезки при развороте, исправления консоли Windows (см. историю).

### 1. Приложение на очках — `app/` (Kotlin, 2D-панель)

- `applicationId org.orikly.queststream`, `minSdk 29`, `targetSdk 34`, `compileSdk 35`. AGP 8.10.1, Kotlin 2.1.21, Gradle 8.14.3. Единственная зависимость — OkHttp 4.12.0 (WebSocket). Разметка экрана в коде, без ресурсов.
- Экран приложения на испанском: имя, IP/порт, «Estado: …», «Servidor: conectado / conectando… / inactivo», кнопка «Iniciar transmisión», подсказка выбрать «Pantalla completa», версия внизу.
- Захват: foreground service типа `mediaProjection` (сначала `startForeground`, потом `getMediaProjection`, `registerCallback` до `createVirtualDisplay`). `VirtualDisplay` (AUTO_MIRROR) сразу в 960p → `ImageReader` RGBA_8888 → Bitmap → JPEG. `PARTIAL_WAKE_LOCK`, WifiLock (LOW_LATENCY + HIGH_PERF).
- Отбор кадров по расписанию ровно каждые 100 мс (экран 72 Гц; простое «≥100 мс» давало ~9 кадров/с). Пока никто не смотрит — JPEG не сжимается, кадр в памяти раз в секунду.
- Новые кадры система даёт только когда экран **меняется**: неподвижный/выключенный экран → новых кадров нет (на ноутбуке ~1 кадр/с повтора).
- **Диагностика:** каждый вызов `onImage` считается (`StreamState.systemFrames`), раз в 2 с — `systemFps` (кадры/с от самой системы, до отбора 10 к/с). Также размер захвата, частота экрана (`Display.refreshRate`), `Build.DISPLAY`. Видно на экране очков («Diagnóstico: sistema … fps · enviados …») и на плитке ноутбука.
- Файлы: `CaptureService.kt` (захват, сжатие, лестницы качества), `StreamState.kt` (общее состояние, константы), `RelayClient.kt` (связь с ноутбуком через интернет), `HttpServer.kt` (локальный режим), `DeviceInfo.kt` (имя, id, IP, батарея, RSSI), `MainActivity.kt`.
- Константы (`StreamState.kt`): `TARGET_FPS 10`, `TARGET_HEIGHT 480`, `HQ_HEIGHT 960`, `NORMAL_LADDER = (480,60) (480,50) (480,40) (400,40) (360,35) (300,30)`, `HQ_LADDER = (960,80) (840,70) (720,65) (600,60) (480,55) (400,45)`.
- Сборочные параметры из секретов: `STREAM_KEY`, `RELAY_URL` → `BuildConfig`.

### 2. Связь очки → ноутбук через интернет (`RelayClient.kt` ↔ `server/main.go`)

- Очки сами держат WebSocket: `wss://stream.orikly.org/push?key=STREAM_KEY` (адрес зашит в APK из секрета `RELAY_URL`). Ping 20 с (Cloudflare рвёт молчащие ~100 с). Переподключение 2 → 30 с.
- Протокол:
  - очки → сервер: text `{"type":"hello","id","name","model","version"}`; `{"type":"status",capturing,fps,sentFps,level,rtt,output,source,sysFps,capture,hz,os,battery,rssi,ip}` раз в 2 с при показе (иначе 10 с); binary = JPEG-кадр.
  - сервер → очки: `{"type":"want","on","hq","acks":true}`; `{"type":"ack"}` на каждый кадр.
  - Сервер передаёт `status` на страницу как есть (новые поля не требуют правки сервера).
- **Подтверждения (с 0.3.3):** в пути не больше 3 неподтверждённых кадров; при занятом окне отправляется самый свежий кадр, как только придёт ack. Без этого задержка росла с 0 до 5–7 с (кадры копились в Cloudflare/буферах при узком интернете ноутбука). Сторож: если 5 с нет ack — окно сбрасывается.
- Адаптация: за 2 с выброшено >10% кадров → ступень качества ниже; 6 с без потерь → выше. При развороте начинается с лучшей ступени HQ.
- Очки различаются по **`id` = ANDROID_ID**, не по имени: на Quest имя у всех одинаковое («Quest 3»), в 0.3.0 из-за этого очки вытесняли друг друга.
- Совместимость: старое приложение + новый сервер и наоборот работают (неизвестные поля игнорируются; acks включаются, только если обе стороны новые).

### 3. Программа-сервер на ноутбуке — `server/` (Go 1.24, gorilla/websocket)

- Один файл без установки: `orikly-server.exe` (Windows) и `orikly-server-mac` (универсальный arm64+x86_64; склеивается `server/fatmacho.py`, т.к. на Linux-раннере нет lipo; Go сам ставит ad-hoc подпись для arm64). В релиз Mac-версия идёт как `orikly-server-mac.zip` (zip сохраняет право на запуск).
- Слушает **только `127.0.0.1:8090`**. Ключ — в `orikly-server.json` рядом с программой (`{"key": "...", "port": 8090}`), спрашивается при первом запуске.
- Эндпоинты: `/push` (WebSocket очков, единственный доступный через туннель); локально: `/` (страница, встроена в программу через `go:embed index.html` — при сборке копируется из `viewer/index.html`), `/api/devices`, `/view/<id>[?hq=1]` (WebSocket кадров для плитки), `/stream/<id>` (MJPEG, для отладки). Запросы через Cloudflare несут `Cf-Connecting-Ip` → всё, кроме `/push`, отвечает 404.
- При запуске открывает Chrome (Mac: `open -a "Google Chrome"`). На Mac держит компьютер бодрствующим: `caffeinate -di -w <pid>`.
- Windows: QuickEdit консоли отключается (`console_windows.go`, без внешних зависимостей, `syscall` + `SetConsoleMode`; на других ОС — `console_other.go`) — клик в окно ставил программу на паузу до Enter и **останавливал поток** (так и было у Paul); лог пишется асинхронно (`console.go`, после ввода ключа), при зависшей консоли строки выбрасываются.
- Строки в окне: `connected: <имя> [<хвост id>] (...) from <ip>`, `disconnected: …`, `rejected a headset with a wrong key …`.

### 4. Страница наблюдателя — `viewer/index.html` (один файл, без зависимостей)

- Два режима: открыта программой-сервером по `http://` → **режим сервера** (очки находятся сами); открыта как файл `file://` → старый локальный режим по IP (Settings: ключ + IP).
- Плитки по `id`, подпись «Quest 3 · хвост id» при совпадении имён; **клик по имени — переименовать** (хранится в localStorage этого Chrome). Известные очки запоминаются.
- Start / Stop на плитке, Start all / Stop all, галочка Record, «Choose folder…» (File System Access API; папка запоминается в IndexedDB).
- Кадры в режиме сервера — по **WebSocket на каждую плитку** (Chrome держит максимум 6 HTTP-потоков к одному адресу; MJPEG по HTTP при 7+ очках вставал в очередь). Рисуется только самый свежий кадр.
- Разворот: клик по картинке → переподключение с `hq=1`; Esc / клик — назад. Canvas `position:absolute` + `min-height:0` (раньше обрезались верх/низ).
- Запись: `canvas.captureStream` с **отдельного canvas фиксированного размера (480)** → MediaRecorder, кодек **`avc3`** (с `avc1` Chrome предупреждал о порче файла при смене размера), куски раз в 2 с в файл `Имя_дата_время.mp4`.
- На плитке: «Streaming · N fps» (реально дошедшие кадры), «⏱ N ms» (отклик очки→ноутбук), «⚠ quality −N» (очки снизили качество), батарея, RSSI; серая строка диагностики «модель · system N fps · sent N fps · capture WxH · screen WxH Hz» (подсказка при наведении: версия приложения и OS); «Capture stopped — tap Iniciar on headset»; «Offline — headset not connected».

### 5. Локальный режим (запасной)

Приложение на очках также поднимает HTTP-сервер `:8080` (`/stream` MJPEG, `/snapshot.jpg`, `/status`, `?key=`, `?hq=1`, CORS + `Access-Control-Allow-Private-Network`). Работает, только если очки и ноутбук в одной сети (в школе сейчас невозможно). На Mac Chrome без разрешения «Локальная сеть» (macOS 15+) даёт `ERR_ADDRESS_UNREACHABLE`.

## Cloudflare (домен `orikly.org`)

- Аккаунт Cloudflare ассоциации (`Office@orikly.org`). DNS домена `orikly.org` перенесён в Cloudflare (сайт и почта ассоциации — в тех же DNS-записях, **их не трогать**).
- Туннель (cloudflared), маршрут — **Published application**: `stream.orikly.org` → **`http://127.0.0.1:8090`** (тип **HTTP**).
- Почему public, а не private hostname: private требует WARP + вход в Zero Trust на каждых очках — на Quest под HMS нереально. Снаружи доступен только `/push` с ключом.
- **Отложенное решение Paul:** Cloudflare Access + Service Token. «Пропуск» (`CF-Access-Client-Id` / `CF-Access-Client-Secret`) зашивается в APK как ключ (секреты GitHub), очки шлют его в заголовках. Посторонние запросы отсекаются на стороне Cloudflare и **до ноутбука не доходят** — это главное. Делать, когда всё заработает.
- Проверка туннеля: при запущенной программе `https://stream.orikly.org/push` → **`forbidden`** = всё работает.

### Грабли Cloudflare, на которые уже наступили

| Симптом | Причина |
|---|---|
| 502 Bad Gateway | В маршруте HTTPS вместо HTTP или `localhost` вместо `127.0.0.1` (на Windows `localhost` → `::1`, а программа слушает `127.0.0.1`); или программа не запущена. |
| 1033 | Адрес ведёт на туннель без живых компьютеров: DNS-запись `stream` (CNAME `<Tunnel ID>.cfargotunnel.com`) указывает на **старый/удалённый туннель**. CNAME должен совпадать с **Tunnel ID** (Tunnel details), а не с Replica ID (Replica ID всегда другой). Новый туннель = новый Tunnel ID = старый CNAME перестаёт работать. |
| «This site can't be reached» | DNS-записи `stream` нет (удалили вместе с маршрутом) или облако серое (DNS only) — нужно Proxied. После исправления — сбросить DNS-кэш. |
| В логе cloudflared `Unauthorized: Tunnel not found` | На компьютере работает cloudflared с токеном удалённого туннеля. |
| `service is already installed` | Сначала `cloudflared service uninstall`. |
| Часть очков не появляется | Туннель работает на двух компьютерах сразу (две реплики) — Cloudflare делит очки между ними. Должна быть **одна** реплика. |
| `rejected a headset with a wrong key` | Ключ в `orikly-server.json` ≠ `STREAM_KEY` из GitHub (у Paul ключ вида `password_1234`). |

Внешний IP школы (через него приходят все очки): `185.197.91.241` — у всех очков одинаковый, различать по id.

## Два компьютера, один туннель

- В Cloudflare **один туннель `stream`**, маршрут `stream.orikly.org → http://127.0.0.1:8090`. Второй туннель не нужен: адрес в APK один, а hostname привязывается только к одному туннелю.
- **Windows (основной):** cloudflared стоит службой, запускается сам. Остановить/запустить: PowerShell от администратора `Stop-Service cloudflared` / `Start-Service cloudflared`.
- **Mac (разработка):** cloudflared **не службой**, а вручную в окне Терминала: `cloudflared tunnel run --token <токен>` (токен — из «Add a replica → macOS», только часть `eyJ…`). Закрыл окно — Mac ушёл из туннеля. Так Mac не перехватит очки во время урока.
- Правило: в Replicas всегда **один** компьютер. Иначе Cloudflare делит очки между компьютерами.
- Прошлая попытка: на Mac мог остаться сервис от удалённого туннеля `stream_vr_macos` → `sudo cloudflared service uninstall`, `sudo pkill cloudflared`; DNS-запись `stream-vr-mac` удалить.
- На Mac уже стоят Homebrew и cloudflared. `orikly-server.json` с Windows не переносится — ключ вводится заново (= `STREAM_KEY`). Google Drive for desktop на Mac ещё не стоит.
- Полный гайд для Paul: `ИНСТРУКЦИЯ-MAC.md`.
